# 手部跟随桌面机械臂 — 设计方案

> 版本：v0.3  
> 日期：2026-03-11  
> 变更：主线定为「仿真臂练控制与进阶 + 真摄像头练跟随感知 + 接口统一 + 真机后置」  
> 定位：可长期演进的低成本具身智能入门项目  
> 预算目标：前期以电脑为主；真机硬件约百元级，后置采购

---

## 1. 背景与目标

### 1.1 为什么做这个项目

具身智能的核心是闭环：

1. **感知**（真摄像头跟踪手部）
2. **映射 / 决策**（手部位姿 → 关节目标）
3. **执行**（先仿真臂，后真机臂）
4. **再调整**（滤波、限速、丢跟踪、安全停；后续可加规划与任务层）

本项目不只做一个 demo，而是搭一条能不断优化进阶的技术主线。

### 1.2 主线策略（已确认）

```text
仿真臂  练控制与进阶
真摄像头 练跟随感知
接口统一 感知/映射不绑死执行器
真机后置 仿真闭环成熟后再买臂
```

### 1.3 目标（Must）

- 不使用遥控器 / 手柄点按控制
- **真摄像头**实时跟踪手部，连续产生跟随控制量
- **物理仿真臂**接收同一套控制接口并实时跟随
- 上层代码通过 `ArmBackend` 切换 `sim / console / serial`，无需改感知逻辑
- 能录制「手在镜头前动 → 仿真臂跟随」演示视频
- 架构支持后续加 IK、轨迹、抓取任务、更好臂模型，而不推倒重来

### 1.4 非目标（Not Now）

- 不第一天就上 Isaac 级重工业仿真
- 不追求真机毫米级复现
- 不做完整力控 / 多物体复杂操作（作为后续里程碑）
- 不把端侧芯片跟随作为第一期验收

### 1.5 成功标准

| 级别 | 标准 |
|------|------|
| P0 | 真摄像头稳定输出手部状态；状态机含 TRACKING/LOST |
| P1 | 仿真臂通过统一接口跟随手部（左右/上下/夹爪） |
| P2 | 控制层具备滤波、死区、限速、限幅；丢跟踪安全冻结 |
| P3 | 同一套上层逻辑可切到串口真机（真机后置） |
| P4（进阶） | 仿真内开始任务化（到达点、简易抓取等） |

## 2. 总体策略

### 2.1 为什么这样拆

| 部分 | 用什么练 | 原因 |
|------|----------|------|
| 感知 | 真摄像头 | 光照、延迟、抖动、丢跟踪必须尽早真实体验 |
| 控制 / 进阶 | 仿真臂 | 可反复试错，不烧舵机，方便加自由度与任务 |
| 接口 | 统一 `ArmBackend` | 换仿真/真机/日志后端时上层不动 |
| 真机 | 后置 | 等控制手感与协议稳定再花钱 |

### 2.2 阶段总览

```text
阶段 0  仓库骨架 + ArmBackend 接口冻结
阶段 1  真摄像头手部跟踪（可先 console 输出）
阶段 2  PyBullet 仿真臂 + 同一接口
阶段 3  手部跟随仿真闭环（主验收）
阶段 4  控制进阶（插值、工作空间、简易 IK 等）
阶段 5  真机后置接入（SerialArmBackend）
阶段 6  端侧迁移（可选，预期降级）
```

### 2.3 设计原则

1. **执行器可替换**：仿真与真机实现同一接口。
2. **协议先稳**：连续控制以关节帧 `J` 为主。
3. **稳定优先于炫技**：滤波 + 死区 + 限速必做。
4. **仿真选轻量可演进**：先 PyBullet，需要再迁 MuJoCo/Isaac。
5. **真机后置**：未达到 P1/P2 不采购机械臂。
6. **进阶加层，不改底**：任务层加在 Backend 之上或之侧，不把感知写死进仿真。

## 3. 统一接口设计（核心）

### 3.1 逻辑架构

```text
┌─────────────────────────────────────────────────────────────┐
│ Perception（真摄像头）                                        │
│ Camera → MediaPipe Hands → HandState + TrackStatus          │
└────────────────────────────┬────────────────────────────────┘
                             │
                             ▼
┌─────────────────────────────────────────────────────────────┐
│ Mapping + Filter                                             │
│ Calib → JointTarget → EMA/OneEuro → Deadband → RateLimit    │
└────────────────────────────┬────────────────────────────────┘
                             │ JointFrame / ControlEvent
                             ▼
┌─────────────────────────────────────────────────────────────┐
│ ArmBackend（统一接口）                                        │
│  connect / close / home / enable / set_joints / get_joints  │
└───────┬─────────────────────┬─────────────────────┬─────────┘
        ▼                     ▼                     ▼
 SimArmBackend        SerialArmBackend       ConsoleBackend
 (PyBullet)           (真机串口, 后置)         (日志调试)
```

### 3.2 接口草案（Python）

```python
class ArmBackend(Protocol):
    def connect(self) -> None: ...
    def close(self) -> None: ...
    def home(self) -> None: ...
    def set_enabled(self, enabled: bool) -> None: ...
    def set_joints(self, j1: float, j2: float, j3: float, grip: float) -> None: ...
    def get_joints(self) -> tuple[float, float, float, float]: ...
```

约定：

- `set_joints` 为**目标角**，后端可内部插值逼近
- 单位：度（全局统一）
- 限幅：后端必须再做一次硬限幅（最终防线）
- 上层可先 clamp，但不假设后端会“听话到无限角度”

### 3.3 命令协议

文本/语义协议见 [`protocols/commands.md`](../protocols/commands.md)。

- 仿真：进程内直接调用 `set_joints`
- 真机：序列化为 `J,<j1>,<j2>,<j3>,<grip>\n`
- 两者语义一致，保证真机后置时只加后端、不改主链路

## 4. 仿真设计

### 4.1 选型

| 阶段 | 引擎 | 理由 |
|------|------|------|
| 第一期（当前） | **PyBullet** | 安装相对简单、Python 友好、够做臂跟随与后续简易接触 |
| 进阶可选 | MuJoCo | 控制/接触研究更常见 |
| 更重可选 | Isaac Sim | 大规模视觉与仿真产线，过早引入成本高 |

结论：主线先锁定 **PyBullet**，接口层隔离引擎，避免写死。

### 4.2 仿真臂模型

第一期：

- 简化 4DOF：底座 yaw + 肩 + 肘 + 夹爪
- 可用 URDF（自建简化模型或开源桌面臂模型改）
- 视觉上能看清关节运动即可，不追求外观精美

进阶：

- 更接近将采购的真机尺寸与关节限位
- 加入桌面、简单物块，为抓取做准备

### 4.3 仿真后端职责

`SimArmBackend` 负责：

1. 加载臂模型与场景
2. 接收 `set_joints` 并驱动仿真步进
3. 关节限幅与可选速度限制
4. 提供调试视角（第三人称看臂）
5. （可选）暴露末端位姿，供以后 IK/任务层使用

不负责：

- 手部识别（那是真摄像头链路）
- 业务手势逻辑

### 4.4 双窗口运行形态（推荐）

```text
窗口 A：摄像头画面 + 手部骨架 + HUD（跟踪状态、pinch、输出角）
窗口 B：PyBullet 仿真臂跟随
```

也允许单进程内左右分栏；实现时以稳定优先。

## 5. 真摄像头感知设计

### 5.1 技术

- OpenCV 采流
- MediaPipe Hands（21 点）
- 默认镜像显示，左右符合直觉

### 5.2 手部状态

```text
HandState:
  x, y          # 主跟随点归一化或像素
  scale         # 手部尺度（粗深度代理）
  pinch         # 拇指-食指距离（归一化）
  status        # TRACKING / LOST
  timestamp
```

主跟随点第一期可配置：

- `INDEX_TIP`：更跟手
- `WRIST`：更稳

### 5.3 跟随映射（模式 A，第一期）

| 输入 | 输出 |
|------|------|
| 手 x | `j1` |
| 手 y | `j2`（可联动 `j3`） |
| pinch | `grip` |
| scale | 可选映射前后；不稳则关闭 |

### 5.4 滤波三件套

1. EMA / One Euro  
2. Deadband（如 <1–2° 不更新）  
3. Rate limit（默认 20Hz 下发）

### 5.5 跟踪状态机

```text
LOST --(连续 hit)--> TRACKING --(连续 miss)--> LOST
                         |
                         v
                   向 Backend 下发关节目标
```

LOST：冻结最后合法目标或缓回 `HOME`（可配置，默认冻结）。

## 9. 实时性预算

| 环节 | 目标 |
|------|------|
| 相机 | 640x480 @ 30FPS（可降） |
| 手部跟踪 | ≥15FPS 有效 |
| 控制下发 | 20Hz 默认 |
| 仿真步进 | 与下发同频或更高，但 UI 保持流畅 |

优先优化：降分辨率 → 隔帧推理 → 减可视化开销。

## 13. 后续演进路线图

```text
手部跟随（仿真）
  → 工作空间/IK
  → 仿真抓取小任务
  → 更好臂模型 / 更真接触
```
