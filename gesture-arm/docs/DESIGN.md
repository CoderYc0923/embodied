# 手部跟随桌面机械臂 — 设计方案

> 版本：v0.2  
> 日期：2026-03-10  
> 变更：交互从「离散手势命令」改为「连续手部动作跟随」  
> 定位：低成本具身智能入门项目（感知 → 映射 → 执行闭环）  
> 预算目标：硬件约百元级；开发期优先使用已有电脑

---

## 1. 背景与目标

### 1.1 为什么做这个项目

具身智能的核心不是「有个外壳」，而是系统能：

1. **感知**环境（本项目：摄像头实时跟踪手部）
2. **决策 / 映射**下一步怎么动（本项目：手部位姿 → 关节目标）
3. **执行**并改变物理状态（本项目：舵机臂连续跟随）
4. **根据结果再调整**（本项目：平滑、丢跟踪保持、限幅与安全停）

本项目用最低成本做出「手在镜头前动，臂跟着动」的可演示闭环。

### 1.2 目标（Must）

- 不使用遥控器 / 手柄 / 手机虚拟摇杆
- 电脑端实时跟踪手部关键点，**连续控制**机械臂运动
- 至少实现平面跟随：手左右 → 底座转；手上下 → 臂抬落；捏合 → 夹爪开合
- 软件分层清晰，便于先虚拟臂验证，再接真机
- 能录制一段「手部移动，机械臂跟随」的演示视频

### 1.3 非目标（Not Now）

- 不追求毫米级、工业级轨迹复现
- 不做完整 6DoF 手腕姿态复刻（滚动/俯仰全跟随）
- 不做力控、碰撞检测、复杂抓取规划
- 第一期不强依赖 MuJoCo / Isaac / Gazebo
- 第一期不把「丝滑连续跟随」作为端侧芯片硬指标（端侧算力与延迟更吃紧）

### 1.4 与旧方案（v0.1 离散手势）的区别

| 维度 | v0.1 离散手势 | v0.2 手部跟随（当前） |
|------|---------------|----------------------|
| 用户体验 | 握拳/挥手触发一次动作 | 手怎么动，臂大致跟着动 |
| 输出 | 偶尔几条命令 | 每秒十几～几十帧关节目标 |
| 难度 | 低 | 中（平滑、标定、延迟是关键） |
| 百元舵机适配 | 容易 | 能做，但会抖，需限频与滤波 |
| 去电脑迁芯片 | 相对容易 | 明显更难 |

### 1.5 成功标准

| 级别 | 标准 |
|------|------|
| P0 | 电脑画面上，虚拟臂 / 光标能稳定跟随手部移动与捏合 |
| P1 | 真机在限幅工作区内连续跟随，肉眼可感知左右/上下/夹爪同步 |
| P2 | 手离开画面不乱甩；重新进入后可恢复跟随；5 分钟演示不明显失控 |
| P3（可选） | 端侧芯片完成降级版跟随（更低帧率、更少自由度也可） |

## 2. 总体策略

### 2.1 三阶段主路径

```text
阶段 A：电脑软测                阶段 B：真机接入              阶段 C：端侧去电脑
摄像头 + 手部跟踪          →    连续关节流控舵机臂      →    视觉芯片本地跟踪
虚拟臂 / 屏幕指针跟随           同一套 J 协议                 降级帧率与自由度
```

说明：

- **先软测再买臂**：先证明跟随手感可接受，再采购。
- 本项目的「仿真」= **虚拟执行器跟随**（屏幕上的臂或十字准星），不是完整物理引擎。
- 连续跟随对延迟敏感：开发期用电脑是正确选择。

### 2.2 设计原则

1. **跟随以「稳定」为第一优先级**，炫技平滑度第二。
2. **PC 算映射，臂端只执行**：第一期下位机接收关节角，不做复杂 IK。
3. **滤波 + 死区 + 限速** 三件套必做，否则百元舵机必抖。
4. **工作空间标定**：把手部活动范围映射到臂的安全关节范围。
5. **丢跟踪安全**：找不到手时停止更新目标，绝不随机乱指。

### 2.3 推荐跟随模式（分两级实现）

#### 模式 A — 2.5D 跟随（第一期主推）

用一只手即可：

| 手部输入 | 臂输出 |
|----------|--------|
| 指尖/手腕在画面中的 **x** | 底座 `j1` |
| 指尖/手腕在画面中的 **y** | 肩/肘合成的「高度/伸展」`j2`（可再拆 `j3`） |
| 拇指–食指距离 | 夹爪 `grip` |

深度（前后）第一期可用「手部整体尺度」做粗近似，不稳定则先关掉。

#### 模式 B — 增强跟随（第二期）

- 手掌法线 / 朝向 → 微调腕关节（若有）
- 双点深度或更稳的尺度滤波 → 前后伸展
- 可选：张开五指暂停跟随、捏合锁定夹爪等「模态手势」作为辅助（跟随仍是主交互）

## 3. 系统架构

### 3.1 逻辑架构

```text
┌──────────────────────────────────────────────────────────────┐
│                     Perception 感知                           │
│  Camera → Hand Landmarks (21) → Tracking State (OK/LOST)     │
└────────────────────────────┬─────────────────────────────────┘
                             │ HandState(x,y,scale,pinch,...)
                             ▼
┌──────────────────────────────────────────────────────────────┐
│                     Mapping 映射                              │
│  Calib → Normalize → Joint Target → Clamp                    │
└────────────────────────────┬─────────────────────────────────┘
                             │ raw joints
                             ▼
┌──────────────────────────────────────────────────────────────┐
│                     Filtering 滤波                            │
│  EMA / One Euro → Deadband → Rate Limit → Send Gate          │
└────────────────────────────┬─────────────────────────────────┘
                             │ JointFrame @ ~20Hz
                             ▼
┌──────────────────────────────────────────────────────────────┐
│                     Execution 执行                            │
│  Transport(Serial) → Firmware (limit) → Servo Arm            │
└──────────────────────────────────────────────────────────────┘
```

### 3.2 部署形态

#### 形态 1：开发态（当前主推）

```text
[笔记本摄像头 / USB 摄像头]
        ↓
[PC: MediaPipe 跟踪 + 映射 + 滤波]
        ↓ Serial  (J,j1,j2,j3,grip)
[Arduino / 套件控制板]
        ↓ PWM
[4DOF 舵机机械臂]
```

#### 形态 2：端侧态（后置，预期降级）

```text
[算力更强的视觉板优先，而非最弱 ESP32-CAM]
        ↓ 较低 FPS 跟踪
[同一 J 协议或板载直驱]
        ↓
[舵机机械臂]
```

> 实话：连续跟随比离散手势更吃 CPU/NPU。阶段 C 可能需要提高预算或接受「更顿的跟随」。

## 4. 手部跟踪与映射设计

### 4.1 关键点选择

使用 MediaPipe Hands 21 点，第一期建议：

| 用途 | 关键点 | 理由 |
|------|--------|------|
| 主跟随点 | 食指指尖 `INDEX_TIP`（8）或手腕 `WRIST`（0） | 指尖更直观；手腕更稳，可配置 |
| 捏合 | 拇指尖 `THUMB_TIP`（4）与食指尖（8）距离 | 控制夹爪 |
| 尺度 / 粗深度 | 掌心相关点形成的手部 bbox 对角线 | 近似前后 |

### 4.2 坐标与镜像

- 画面默认 **镜像显示**（`mirror=true`），用户举手方向与臂运动方向符合直觉。
- 内部计算在镜像后坐标系进行，避免左右反了还要靠用户反向脑补。

### 4.3 归一化与标定

不做复杂相机标定也可以先跑起来，但要做 **工作空间标定**：

1. 用户将手依次放到画面中的「左、右、上、下」舒适边界，按键记录  
2. 得到手部像素范围：`x_min/x_max/y_min/y_max`  
3. 映射到关节范围：`j_min/j_max`（安全限幅内）

线性映射示例：

```text
j1 = lerp(j1_min, j1_max, (x - x_min) / (x_max - x_min))
j2 = lerp(j2_min, j2_max, (y - y_min) / (y_max - y_min))
grip = lerp(grip_open, grip_close, saturate(pinch_norm))
```

`pinch_norm`：把拇指–食指距离按手部尺度归一化，避免手远离镜头时「捏合变大」。

### 4.4 夹爪映射

| 捏合距离（归一化） | 夹爪 |
|--------------------|------|
| 大（张开） | `grip` → 打开 |
| 小（捏住） | `grip` → 闭合 |
| 中间 | 连续插值 |

可加少量滞后（hysteresis），避免在阈值附近抖动开合。

### 4.5 滤波三件套（必做）

1. **EMA 或 One Euro Filter**：抑制关键点抖动  
2. **死区 Deadband**：关节角变化 `< 1～2°` 不更新发送  
3. **限频 Rate Limit**：串口发送上限 20Hz；单帧关节变化限速，防止舵机狂追

### 4.6 跟踪状态机

```text
LOST ──(连续 Hit 帧)──► TRACKING ──(连续 Miss 帧)──► LOST
                          │
                          ▼
                     发送 J 帧

LOST 期间：不发送新目标；可选慢速回 HOME 或冻结
```

参数建议初值：

- `hit_frames = 3`
- `miss_frames = 8～12`
- `send_hz = 20`
- `ema_alpha = 0.3～0.5`（按手感调）

## 5. 通信协议（v2）

详见 [`protocols/commands.md`](../protocols/commands.md)。

摘要：

- 主数据路径：`J,<j1>,<j2>,<j3>,<grip>\n`
- 辅控制：`PING` / `HOME` / `ENABLE` / `DISABLE`
- 波特率：`115200`
- 固件必须做关节限幅；超限夹紧到边界并可读 `ERR:RANGE`（可选）

第一期不采用高频自定义二进制协议，优先调试效率；若 20Hz 文本成为瓶颈再升级。

## 6. 技术选型

### 6.1 电脑端（阶段 A/B）

| 层级 | 技术 | 用途 |
|------|------|------|
| 语言 | Python 3.10+ | 主开发 |
| 采集 / 可视化 | OpenCV | 摄像头、画骨骼与虚拟目标 |
| 手部跟踪 | MediaPipe Hands | 21 点实时骨架 |
| 滤波 | 自写 EMA；可选 One Euro | 平滑 |
| 串口 | pyserial | 发送 `J` 帧 |
| 数值 | numpy（可选） | 映射与滤波方便 |

### 6.2 下位机与机械臂（阶段 B）

| 项目 | 建议 |
|------|------|
| 机械臂 | 4DOF 舵机套件（带板） |
| 固件职责 | 解析 `J`、限幅、写 PWM；可做简单插值追目标 |
| 供电 | 舵机独立 5V 大电流，与逻辑共地 |
| 结构 | 底座固定，减少跟随晃动 |

固件插值建议：

- 收到新目标后，以有限角速度逼近，而不是瞬间跳变  
- 这样 PC 偶发丢帧也不会让舵机「瞬移撕裂」

### 6.3 端侧（阶段 C）

| 方案 | 对跟随的适配 |
|------|----------------|
| ESP32-CAM | 偏吃力，可能只能低帧粗跟随 |
| K210 / 更强 NPU 模组 | 更值得尝试 |
| 仍保留轻量 PC（笔记本） | 学习阶段完全合理 |

## 7. 阶段步骤（详细）

### 阶段 0：准备与约定（0.5～1 天）

- [ ] 确认摄像头可用
- [ ] 冻结：主跟随点用指尖还是手腕
- [ ] 冻结：`J` 协议字段与角度单位
- [ ] 建虚拟环境与目录骨架

交付：环境可运行 `python -V`，设计与协议已对齐 v0.2。

---

### 阶段 1：跟踪软测 + 虚拟跟随（3～5 天）

**不买臂也能做完。**

任务：

- [ ] OpenCV 取流 + 镜像显示
- [ ] MediaPipe 画手部骨架
- [ ] 提取 `(x, y, pinch, scale)`
- [ ] 实现线性映射到「虚拟关节」或屏幕准星
- [ ] EMA + 死区 + 20Hz 发送门控（先打到控制台）
- [ ] 跟踪状态机：丢失手则冻结
- [ ] HUD：FPS、跟踪状态、输出 `J` 帧、pinch 值

验收（P0）：

- 手左右/上下移动时，虚拟目标平滑跟随
- 捏合变化时虚拟夹爪连续变化
- 抽走手后虚拟臂不乱跳

---

### 阶段 2：标定工具 + 串口 dry-run 完善（1～2 天）

- [ ] 简单标定流程（记录手部活动四边界）
- [ ] `ConsoleTransport` / `SerialTransport` 切换
- [ ] `ENABLE`/`DISABLE` 逻辑（空格键暂停跟随）
- [ ] smoke test：手动发送若干 `J` 帧

验收：

- 标定后，手在舒适区内，输出关节覆盖期望范围且不越限
- 暂停键可立即停止发送

**此阶段结束后再采购机械臂。**

---

### 阶段 3：真机接入（3～7 天，含物流）

#### 采购参考（百元级）

| 物料 | 预算 |
|------|------|
| 4DOF 舵机臂套件 | 50–90 元 |
| 5V 足够电流电源 | 强烈建议预留 |
| 摄像头 | 优先笔记本自带 |

#### 联调顺序

1. 固件：`PING` / `HOME`  
2. 慢速脚本逐步发送 `J` 扫描各关节  
3. 开跟随但降低 `send_hz`（如先 10Hz）  
4. 再开夹爪连续映射  
5. 最后把滤波调到「跟得上又不疯抖」

验收（P1/P2）：

- 手移动，臂能同向跟随
- 丢失手部时臂保持/安全停
- 演示 5 分钟无协议崩溃

安全：

- 初次跟随把关节范围收得很窄  
- 手远离夹爪咬合区  
- 异常抖动立刻 `DISABLE` 或断电  

---

### 阶段 4：端侧迁移（可选）

目标降级为可接受：

- FPS 10～15 也可
- 先只跟随 `j1 + grip`，再加 `j2`
- 优先选有 NPU / 更强芯片的板，而不是硬上最弱摄像头模组

## 8. 实时性与性能预算

| 环节 | 目标 |
|------|------|
| 相机 | 640x480 @ 30FPS（可降） |
| MediaPipe | 尽量 ≥15FPS 有效跟踪 |
| 控制发送 | 15–30Hz，默认 20Hz |
| 端到端体感延迟 | 尽量 < 150–200ms；百元舵机本身会再拖一点 |

优化顺序：

1. 降分辨率  
2. 隔帧推理（跟踪可用预测/保持）  
3. 减绘制开销  
4. 最后才考虑换模型 / C++  

---

## 9. 安全与可靠性

### 9.1 软件

- 固件硬限幅（最终防线）
- PC 映射后再 clamp 一次
- `DISABLE` 热键
- 丢跟踪冻结
- dry-run 模式

### 9.2 硬件

- 舵机供电充足、共地
- 底座固定
- 线材防卷入关节
- 长时调试给舵机休息

### 9.3 预期缺陷（需在 demo 时诚实接受）

- 快速甩手时臂会滞后
- 低端舵机有抖动与啸叫
- 深度（前后）近似会漂
- 强逆光跟踪丢帧

这些不阻挡入门，但决定了它是「教学/作品集 demo」而非产品。

## 12. 采购决策门槛

同时满足再买臂：

1. 虚拟跟随已经「你自己觉得跟手」  
2. 滤波参数有一套可用默认值  
3. `J` 协议与关节限幅策略已写清  
4. 预算仍够臂 + 电源  

若虚拟跟随都嫌延迟/抖动不可接受，先调软件，不要指望换臂奇迹翻盘（百元舵机只会更钝）。
